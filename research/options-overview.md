[Otto](https://github.com/Open-Hardware-Leaders/OttoDIY), [его библиотека](https://github.com/OttoDIY/OttoDIYLib), [Q8bot](https://github.com/EricYufengWu/q8bot), [Open Duck](https://github.com/apirrone/Open_Duck_Mini).

Цифры из авторских BOM не равны актуальной корзине с доставкой в РФ. Для Q8bot нужны конкретные XL330-M077-T, не похожие китайские сервы; импорт снижает привлекательность этого варианта по цене. Штатный Q8bot получает рассчитанные на ноутбуке углы через ESP-NOW, локальная походка не готова в исходной инструкции. Open Duck требует точной версии STS3215 7,4 В/19 кгс·см; 12-вольтовые и другие редукторы не эквивалентны.

Microduck — отдельный продукт: 25 см, предзаказ $399, открыто ПО. [Официальный press kit](https://pollen-robotics.com/microduck/press-kit/) ограничивает слово open source программным обеспечением и не заявляет открытые механические/электронные design files. Отдельные опубликованные HAT/симуляционные STL не означают полного официального DIY-пакета. Поэтому это программный и визуальный ориентир, не выбранная база для собственной открытой механики.

## CAD, симуляция и управление

Для собственной локальной параметрической механики подойдёт [FreeCAD](https://www.freecad.org/features.php). [Onshape Free](https://www.onshape.com/en/pricing) удобен для сборок и экспорта, но документы публичные и тариф для некоммерческого применения. [Onshape-to-robot](https://onshape-to-robot.readthedocs.io/en/latest/) поддерживает URDF/SDF/MuJoCo. Рабочий проект желательно хранить как параметрический CAD/STEP; STL полезен для печати и визуализации, но не сохраняет историю и суставы.

Начать разумно с [MuJoCo](https://mujoco.readthedocs.io/en/stable/modeling.html): оси суставов, массы, центры масс/инерции, моторные ограничения, задержки, контакты и трение нужно добавить к геометрии. Для Q8bot нужны ограничения, замыкающие пятизвенные механизмы. [Webots](https://github.com/cyberbotics/webots) удобен для сцен, датчиков и контроллеров; есть [URDF-конвертер](https://github.com/cyberbotics/urdf2webots). Готовые официальные среды MuJoCo/Webots и RL-политики Otto/Q8bot в проверенных материалах не найдены. У Open Duck такой путь есть.

[Isaac Lab](https://docs.nvidia.com/isaaclab/3.0/isaac-lab/installation) подходит для параллельного обучения, но повышает требования к системе. В текущей версии Newton может работать без полного Isaac Sim; нельзя переносить RTX-требования Isaac Sim на все режимы Lab. Для собственного первого стенда покупать GPU пока не нужно. Готовую походку можно запускать без её обучения, а совместимость конкретного проекта с ОС/стеком проверять по зафиксированной версии.

Лёгкие декоративные панели при близких массах/центрах тяжести требуют проверки, но обычно не новой кинематики. Цвет менять просто. Длины ног, оси, количество суставов, приводы/редукторы, тяжёлая голова и батарея меняют физику: модели/траектории обновляют, RL-политику часто переобучают. Политика одного робота не переносится на другой по совпадению числа приводов.

Выбран собственный облик на основе простой шестисервовой архитектуры: четырёхсервовое основание Otto-подобного типа и двухосевая голова. Документ следующего этапа: ../design/v1/robot-design.md. Это новая компоновка с обязательным испытанием нагрузки; готовая ходьба на увеличенной массе не заявляется.
